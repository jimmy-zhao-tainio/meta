# Security Policy

## Supported versions

`meta` is pre-release software. Security fixes are made on the current default
branch; older commits and development package versions are not maintained as
separate supported release lines.

## Reporting a vulnerability

Please do not publish vulnerability details in a GitHub issue. Use **Report a
vulnerability** on the repository's Security tab when private vulnerability
reporting is available. If that option is unavailable, open a minimal issue
requesting a private contact channel and include no exploit, secret, or
sensitive environment details.

Reports should identify the affected component and version, the impact, and a
minimal reproduction where it can be shared safely. You can expect an initial
acknowledgement before any public disclosure or remediation discussion.
